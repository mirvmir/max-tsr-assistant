# Проверка первого сценария на реальных источниках

Сценарий использует 12 публичных предложений Ortonica и Medicamarket, наблюдавшихся
30 сентября 2026 года и независимо сверенных по страницам. Пользователь и его
ответы синтетические; правила подбора, маршрут и шаблоны — явно обозначенная
demo-модель. Персональные сведения для этой проверки не нужны. Локальный эмулятор
выполняет application/DB/worker/render/download и не отправляет сообщения в MAX.

## Карточка покупки

После первого запуска из README выполните:

```bash
docker compose exec app tsr validate-data --manifest data/releases/real-1.1.0/manifest.json
docker compose exec app tsr demo --dataset public --scenario purchase --download-dir /tmp/tsr-purchase --show-dialog
mkdir -p var/purchase
docker compose cp app:/tmp/tsr-purchase/. var/purchase/
```

При локальном запуске без Docker используйте те же команды `tsr` после настройки
PostgreSQL и переменных из runbook. Каждый запуск создаёт новый кейс; текущие файлы
перечислены в строках `Downloaded:`. Область `<TSR_BOT_SCOPE>:demo:public` отделена
от рабочего active release и очередей бота.

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | Выбрать «Для себя» и создать новый кейс | Показаны роль, demo-режим и граница технической сверки |
| 2 | Подтвердить ширину 405 мм, массу 100 кг, складную конструкцию «да» | Каждый ответ сначала показывается кандидатом; ввод не сохраняется без подтверждения |
| 3 | Подтвердить 10 000 ₽ сертификата и заявленную применимость «да» | Это сведения пользователя, успешная оплата сертификатом ещё не подтверждена |
| 4 | Открыть каталог и выбрать Ortonica Base 200, SKU 5048 | Снимок `079f6eca-6fb4-5b90-b7ca-c21d0d290113`; сиденье 405 мм, нагрузка 130 кг; три технических поля совпадают |
| 5 | Выбрать карточку покупки | Цена 14 500 ₽, условное покрытие 10 000 ₽, условная разница 4 500 ₽; доставка неизвестна, окончательная сумма отсутствует |
| 6 | Прочитать и подтвердить preview | Поставщик, комплектация, реальные источники, дата наблюдения и неизвестные условия видны до создания файлов |
| 7 | Дождаться worker, открыть «Мои материалы» и скачать | `ready`, `files=1`, `gap=450000 kopeks`; PDF начинается `%PDF-` |

`comparison=complete` означает совпадение введённых значений с опубликованными
характеристиками по demo-правилам. Это не заключение о медицинской пригодности.
`pricing=incomplete`, `certificate_use=conditional`, `possible_own_total=null` —
ожидаемый честный результат. Кнопка сертификата на сайте не заменяет проверку
оплаты конкретного заказа; договор фонда также неизвестен.

Откройте PDF. Проверьте кириллицу, DEMO, имя реального поставщика, SKU, 405 мм,
14 500 ₽, условную разницу 4 500 ₽, неизвестную доставку, URL и дату наблюдения.
Цена и источник не должны называться синтетическими. Hash содержимого preview и
manifest должен совпадать; SHA-256 приведён в выводе. Все значения документа
взяты из подтверждённого frozen content.

## Полный каталог и неоднозначности

В UI каталог показан по три предложения с кнопками следующих/предыдущих страниц.
Проверьте доступ к предложениям обоих продавцов и последней странице. Для
Medicamarket Base 200, SKU 00-00046407, цена «от 16 724 ₽» должна остаться нижней
границей: точные покрытие, разница и итог по ней не рассчитываются. Комплектация
содержит конфликт шин заголовка и таблицы. Для Base Lite 300, SKU 00-00048055,
цены 33 141 и 31 957 ₽ конфликтуют; система показывает неопределённость. Base Lite
350 имеет конфликт наличия, который не превращается в подтверждённый склад.

## Черновик обращения и прежняя регрессия

```bash
docker compose exec app tsr demo --dataset public --scenario support --download-dir /tmp/tsr-support --show-dialog
mkdir -p var/support
docker compose cp app:/tmp/tsr-support/. var/support/
docker compose exec app tsr demo --dataset synthetic --scenario both --download-dir /tmp/tsr-legacy
```

Новая ветка обращения ожидает `ready`, `files=4`: заявление DOCX, заявление PDF,
карточка изделия PDF, чек-лист PDF. Все четыре файла относятся к одному manifest
и реальному SKU. Регион `ru-alt`, условие маршрута, имя «Демонстрационный Заявитель»
и адрес — учебные сведения. Адресат и чек-лист являются моделью; заявление не
отправляется и не является утверждённым официальным бланком.

Старый набор 1.0.0 сохранён отдельно. Его цена 120 000 ₽ и сертификат 100 000 ₽
дают прежние 20 000 ₽ разницы. `--role representative` проверяет роль представителя;
`--scenario both` — обе ветки. Synthetic demo не меняет active pointer рабочего
бота или public demo.

## Ручная проверка UI в подключённом MAX

После настройки тестового бота, HTTPS и subscription по runbook:

1. В личном диалоге выберите роль и пройдите значения первого сценария. Проверьте
   варианты «Не знаю», «Назад», «Помощь», «Мои кейсы», «Мои материалы».
2. Откройте все страницы каталога. Вернитесь назад: подтверждённые ответы должны
   сохраниться, а старые и чужие кнопки не должны выбирать другой результат.
3. До подтверждения кандидата откройте помощь и продолжите кейс: кандидат должен
   вновь показываться для явного подтверждения; просроченный не подтверждается.
4. Создайте второй кейс, затем откройте первый через «Мои кейсы». Кейсы прежнего
   профиля сохраняют ответы и исторические материалы, новый профиль выбирается
   через создание нового кейса.
5. Смените ответ, предложение или ветку. Прежнее подтверждение изменённого
   содержимого должно стать недействительным. Прочтите все части длинного preview
   до появления подтверждения.
6. Скачайте файл в мобильном и веб-клиенте, повторно откройте материалы. При
   неопределённой доставке повтор требует явного согласия с риском дубликата.
7. Удалите кейс с подтверждением. Доступ и старые кнопки должны сразу отказать;
   `tsr cleanup` и `tsr maintenance` доводят физическую очистку до конца.

Эти живые проверки пока требуют токена, HTTPS endpoint и двух настоящих клиентов.
Локальный тест их не заменяет. Итоговые результаты и оставшиеся требования
приведены в `docs/verification` и `IMPLEMENTATION_STATUS.md`.
