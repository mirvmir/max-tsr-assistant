## Сильные стороны

- Модульный монолит и PostgreSQL inbox/jobs/outbox соразмерны первой версии. Pure domain не импортирует application, SQL или MAX. Длительный рендер вынесен в отдельный `spawn`-процесс; отправка выполняется вне пользовательской транзакции.
- Подтверждённый ввод отделён от кандидата. Owner, semantic/dialog revisions и deletion epoch проверяются при обращении к кейсу. Preview фиксирует полное содержание; manifest копируется из него без пересчёта и сохраняет тот же hash.
- Транзакции имеют явного владельца; scoped dedupe, `SKIP LOCKED`, fence/lease CAS и tombstone защищают повторную обработку и доступ. Durable `sending` предшествует внешнему вызову; неизвестный результат не повторяется автоматически.
- Пользовательские DTO и файлы зашифрованы, identity индексируется HMAC. Webhook минимизирует вход, проверяет секрет и подтверждает приём только после commit. UUID/handle другого пользователя не даёт доступ к его материалам.
- Сравнение сохраняет unknown/mismatch; неизвестные деньги и доставка не становятся нулём. Отказ в приёме сертификата и заявленная неприменимость имеют отдельные основания. Предварительный маршрут не объявляется одобрением фонда.
- В русском диалоге есть явная роль, подтверждение, возврат, смена выбора, страницы полного длинного ответа и истории. DEMO и незаполненные поля видны в диалоге и документах. Отсутствие реальных данных обозначено явно.

## Замечания

### Critical — критические

Подтверждённых Critical в пределах синтетической первой реализации не обнаружено.

### Important — существенные

Блокирующих Important в пределах синтетической первой реализации после исправлений не осталось. Найденный в дополнительном проходе бесконечный crash-retry устранён: recovery учитывает лимит попыток и bot scope, а terminal job и failed bundle с доступным продолжением фиксируются одной транзакцией. Последняя регрессия оставшегося `sending` у terminal job также закрыта: он становится `delivery_unknown`, работа не возрождается и автоматической повторной отправки нет. Подробности и границы проверки приведены ниже.

### Minor — неблокирующие улучшения

- `src/tsr/worker/dispatcher.py:311`, `src/tsr/adapters/db/database.py:505`: hard deadline доказан для render child. Завершение delivery thread и SQL не имеет общего wall-clock deadline; `shutdown(wait=False)` не гарантирует выход интерпретатора при зависшем IO. Compose задаёт внешнюю границу остановки 30 секунд, но это не доказательство полного graceful shutdown. До пилота нужны DB/connect/statement limits и проверка аварийной остановки доставки.
- `src/tsr/application/service.py:104,179`, generic repository list methods: навигация и материалы читают/расшифровывают всю историю; `_latest_question` повторно загружает handles в цикле. Для небольшого demo допустимо, для роста нужны bounded queries, индексы и pooling.
- `src/tsr/worker/dispatcher.py:57`: принудительное завершение использует внутренний атрибут `ProcessPoolExecutor._processes` для Python 3.12/3.13. Регрессия реального зависшего child полезна; при обновлении Python этот путь необходимо проверять заново.
- Application остаётся большим классом, а Protocol-порты описывают только часть используемой поверхности. Дальнейшее разбиение лучше делать по use cases с сохранением одного владельца транзакции.

Также исправлен текст условной доставки: он появляется только для `delivery.paid_by_user`. В дополнительном UI diff показывается ограниченное по длине человекочитаемое название источника, без подмены synthetic источника реальной ссылкой.

## Архитектура, UX и эксплуатационная граница

| Критерий | Оценка по доступным доказательствам |
| --- | --- |
| Соответствие первой demo-цели | Обе ветки воспроизводятся через настоящий CLI/application/queues/render/files с локальным transport |
| Согласованность и безопасность состояния | Owner/revision/epoch/fence/hash/send и конечность crash-recovery реализованы и имеют содержательные регрессии |
| Удобство диалога | Исправление выбора и длинный ввод доступны, неизвестность объясняется; оценка основана на коде, transcript и локальных тестах |
| Соразмерность архитектуры | Разумная простая основа без лишнего брокера; «оптимальная» или «масштабируемая до N» без нагрузки не доказано |
| Развёртывание | CLI проверен; Dockerfile/Compose статически просмотрены. Non-root UID 10001, общий private volume, закрытый порт БД, host secret directory 0700 и read-only mounts согласованы; контейнерный запуск не проверен |
| Готовность пилота | Не установлена; явные программные доработки и внешние данные перечислены ниже |

Не завершены именно **программные работы**: scheduled retention (кейс/manifest 90 дней, чувствительный inbox 24 часа, dedupe 30 дней, файлы семь дней), physical expiry/orphan janitor, persistent worker heartbeat/queue metrics и расширенная readiness, общий rate limiter нескольких workers, per-package lifecycle, generic active-release loading, encrypted backup/restore с replay удаления и полноценные операционные CLI import/activate/rollback/revoke. Ручной tombstone cleanup и запрет чтения expired файла не заменяют планировщик retention. Wheel не содержит весь release payload; поддержан checkout/editable/image layout.

## Рекомендации

Принимать синтетическую первую реализацию с перечисленными пределами; найденные блокирующие дефекты исправлены и финальный набор прошёл. До пилота выполнять эксплуатационные доработки и получать reviewed данные; увеличение числа workers требует общей rate quota и измерений. Весь исходный backlog не следует отмечать выполненным на основании локальных сценариев.

## Что намеренно не оценивалось

- Медицинская пригодность и правильность физических критериев: нет утверждения профильного эксперта, используются учебные правила.
- Реальные цены, наличие, условия поставщиков, приём сертификата и договор с фондом: предложения вымышленные, verified snapshots отсутствуют.
- Юридическая применимость маршрута, адресат, официальный бланк и итоговое решение организации: маршрут и шаблоны synthetic.
- Правовое основание и процесс обработки персональных данных в пилоте: политика/владелец процесса не предоставлены; pilot fails closed.
- Реальная доставка MAX, subscription, TLS цепочка и скачивание в mobile/web: нет токена, опубликованного HTTPS и сессии клиентов.
- Чистая Docker build/run и лимит времени сборки: Docker binary/daemon недоступен в проверенной среде.
- Throughput, p95, fairness и ресурсная ёмкость: нагрузочные измерения не выполнялись.
- Успешное восстановление backup и невоскрешение удалённых данных после restore: соответствующего процесса и эксперимента пока нет.
- Полная пользовательская сравнительная проверка: нет наблюдений реальных участников и протокола mobile/web.
- Сроки, FAQ, закрытый служебный слайд и готовность комплекта сдачи: полный актуальный набор правил не предоставлен.
- OCR, LLM, платежи, государственный login и mini-app: исключены из согласованной реализации.
